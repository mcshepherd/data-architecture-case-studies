# Hashing edge cases

Generated by `scripts/prove-resilience.sh`. Do not edit by hand. Run on 2026-10-14.

Each case makes one targeted change to one row in the ERP, then runs the sync on that table and audits it. The "naive hash" column shows whether an obvious first-draft row hash would even notice: text as-is, everything else by default conversion, NULL as an empty string, a single-pipe delimiter, and no `varchar(max)`. Where it says **No**, a sync built on it would silently keep the old row.

| Change | Column | Before | After | Naive hash sees it? | Sync | Audit |
|---|---|---|---|---|---|---|
| NULL becomes an empty string | `tm_expense_3.note_032` | NULL | '' | **No** | 1 changed | clean |
| money changes in the fourth decimal place | `tm_expense_3.total_004` | 27563.3800 | 27563.3801 | **No** | 1 changed | clean |
| float changes in the 13th significant digit | `tm_expense_3.factor_035` | 1.7917896271428570e+008 | 1.7917896271446490e+008 | **No** | 1 changed | clean |
| datetime changes by 10 milliseconds | `tm_expense_3.entered_at_014` | 2013-09-08 04:37:28.047 | 2013-09-08 04:37:28.057 | **No** | 1 changed | clean |
| a pipe moves from one column to the next | `tm_expense_3.status_028`, `code_029` | status_028 = 'ab', code_029 = '\|cd' | status_028 = 'ab\|', code_029 = 'cd' | **No** | 1 changed | clean |
| a change past the 4,000th character of the row | `pj_milestone.name_298` | row text length 7653, last text column ends xxx | row text length 7653, last text column ends xxy | **No** | 1 changed | clean |
| a new key whose code contains quotes | `ar_receipt` | — | code `O'Brien's` | — | 1 new | clean |
| a deleted key is re-created with new values | `ar_receipt` | row present | deleted, then re-created | — | 1 deleted, then 1 changed | clean |

Why the sync's hash sees every one:

- **NULL versus empty string:** NULL is replaced by `CHAR(0)`, which no text value contains, so NULL and `''` hash differently.
- **money, float, datetime:** each type is cast with an explicit style that keeps full precision: money style 2 (four decimals), float style 3 (17 significant digits), datetime style 121 (milliseconds). The default conversions round money to two decimals, float to six significant digits, and datetime to the minute.
- **A pipe moving between columns:** the delimiter is `$|$`. With a single pipe, `'ab|' + '|' + 'cd'` and `'ab' + '|' + '|cd'` are the same string.
- **Past 4,000 characters:** the concatenation starts from a `varchar(max)`. Without one, SQL Server silently truncates it: at 8,000 characters, or at 4,000 as soon as an `nvarchar` column joins in. The row here is about 7,650 characters, and the change is near its end.
- **Quotes in keys:** keys go back to the ERP as literals in a `VALUES` list, with every quote doubled. One unescaped quote would break the whole batch.
- **A re-created key:** a key that disappears is flagged deleted; when it comes back, it is treated as changed, so the old row is replaced rather than left flagged.
