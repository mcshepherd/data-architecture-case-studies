## Where the old process goes wrong
 
The full-reload tables stay correct: they are rebuilt every night. The damage is all in the incremental tables, which trust the create and modify dates and upsert on the package's key.

- **Missing and stale rows:** rows whose create or modify date is missing, or was not updated when the row changed, are never pulled. And where the package key is missing a column, one pulled row overwrites every sibling that shares the partial key, so the siblings' own values disappear.
- **Duplicated keys:** that overwrite includes the key column the package does not know about, so distinct rows become copies of one row.
- **Deleted rows still present:** the ERP leaves no trace of a delete, and the incremental package has no way to notice one.
