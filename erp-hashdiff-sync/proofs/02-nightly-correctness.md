## What changed in the ERP
 
These are the UPDATE statements the ERP's own business activity ran, from the simulator's log, which the sync cannot see. Some of them write the value a column already holds, such as setting a bit to 1 when it is already 1. The row does not change, so its hash does not change, and the sync correctly does nothing: no fetch, no write. That is why the sync's "changed" count runs below updates plus re-created keys here. The gap is largest when a busy table's only updated column is a bit: on night 3, every update to `bl_fee` rewrote one bit column, and most wrote the value it already had. The audit confirms no real change was missed.
